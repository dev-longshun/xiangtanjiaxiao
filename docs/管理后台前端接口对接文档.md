## 一、投稿审核模块

### 1.1 获取评价列表

**前端调用**：`adminAPI.getReviews(status)`

**请求**：

- 方法：`GET`
- 路径：`/api/admin/reviews` 或 `/api/admin/reviews?status={status}`
- 参数：`status` 可选值：`PENDING`、`APPROVED`、`REJECTED`，不传则返回全部

**期望响应**：

```json
{
  "code": 200,
  "message": "success",
  "data": [
    {
      "id": 1,
      "schoolId": "xiangtan-xxx",
      "schoolName": "湘潭XX驾校", // 需要关联查询驾校名称
      "author": "用户昵称",
      "content": "评价内容...",
      "rating": 5,
      "evidenceImages": ["http://xxx/1.jpg", "http://xxx/2.jpg"],
      "status": "PENDING",
      "rejectReason": null,
      "createdAt": "2025-12-15T10:30:00",
      "reviewDate": "2025-12-15T10:30:00"
    }
  ]
}
```

**前端使用字段**：

- `id`：评价 ID，用于审核操作
- `schoolId`：驾校 ID
- `schoolName`：驾校名称（显示用，如后端未返回则显示 schoolId）
- `author`：评价者昵称
- `content`：评价内容
- `rating`：评分（1-5）
- `evidenceImages`：证明图片数组
- `status`：状态（PENDING/APPROVED/REJECTED）
- `rejectReason`：驳回原因（status=REJECTED 时显示）
- `createdAt` 或 `reviewDate`：创建时间

---

### 1.2 审核评价（通过/驳回）

**前端调用**：`adminAPI.reviewApproval(id, approved, rejectReason)`

**请求**：

- 方法：`POST`
- 路径：`/api/admin/reviews/{id}/review`
- 请求体：

```json
{
  "approved": true, // true=通过，false=驳回
  "rejectReason": "" // 驳回时必填，10-200字符
}
```

**期望响应**：

```json
{
  "code": 200,
  "message": "评价已通过" // 或 "评价已拒绝"
}
```

**业务逻辑**：

- 通过时：更新 `status = 'APPROVED'`，重新计算驾校评分
- 驳回时：更新 `status = 'REJECTED'`，保存 `rejectReason`

### 2.2 获取驾校详情

**前端调用**：`schoolAPI.getSchoolById(id)`（复用现有接口）

**请求**：

- 方法：`GET`
- 路径：`/api/schools/{id}`

**期望响应**：同上，返回单个驾校对象

---

### 2.3 创建驾校

**前端调用**：`adminAPI.createSchool(school)`

**请求**：

- 方法：`POST`
- 路径：`/api/admin/schools`
- 请求体：

```json
{
  "id": "xiangtan-newschool",
  "name": "新驾校名称",
  "namePinyin": "xinjiaxiaomingcheng",
  "address": "详细地址",
  "phone": "联系电话",
  "businessHours": "营业时间",
  "priceRange": "价格范围",
  "description": "驾校简介",
  "tags": "[\"标签1\",\"标签2\"]",
  "courses": "[\"C1\",\"C2\"]"
}
```

**期望响应**：

```json
{
  "code": 200,
  "message": "驾校创建成功"
}
```

**注意**：

- `id` 由前端生成，格式为小写字母、数字、连字符
- `tags` 和 `courses` 前端会序列化为 JSON 字符串

---

### 2.4 更新驾校

**前端调用**：`adminAPI.updateSchool(id, school)`

**请求**：

- 方法：`PUT`
- 路径：`/api/admin/schools/{id}`
- 请求体：同创建驾校（不含 id 字段）

**期望响应**：

```json
{
  "code": 200,
  "message": "驾校更新成功"
}
```

---

### 2.5 删除驾校

**前端调用**：`adminAPI.deleteSchool(id)`

**请求**：

- 方法：`DELETE`
- 路径：`/api/admin/schools/{id}`

**期望响应**：

```json
{
  "code": 200,
  "message": "驾校删除成功"
}
```

**业务逻辑**：执行逻辑删除（`is_active = 0`）

## 三、登录接口补充（⚠️ 需后端修改）

### 3.1 登录响应需包含角色

**现有接口**：`POST /api/auth/login`

**当前响应**（仅返回 token）：

```json
{
  "code": 200,
  "message": "登录成功",
  "data": {
    "token": "eyJhbGc..."
  }
}
```

**期望响应**（需增加 username、nickname、role 字段）：

```json
{
  "code": 200,
  "message": "登录成功",
  "data": {
    "token": "eyJhbGc...",
    "username": "10001",
    "nickname": "用户昵称",
    "role": "ROLE_ADMIN"
  }
}
```

**后端修改位置**：`AuthController.java` 第 48-56 行的 `login` 方法

**前端逻辑**：

- `role === 'ROLE_ADMIN'` → 跳转 `/admin`
- 其他 → 跳转 `/`

## 四、权限控制

### 4.1 前端权限守卫

`AdminLayout.jsx` 在加载时检查：

1. `localStorage.getItem('token')` 是否存在
2. `localStorage.getItem('role')` 是否为 `ROLE_ADMIN`

不满足条件则跳转到登录页或首页。

### 4.2 后端权限要求

所有 `/api/admin/*` 接口需要：

1. 请求头携带有效 JWT Token
2. Token 对应用户角色为 `ROLE_ADMIN`
