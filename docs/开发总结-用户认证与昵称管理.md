## 二、核心功能实现

### 2.1 支持昵称登录

**需求背景**：  
前端希望用户既可以使用系统生成的数字ID（如 `10001`），也可以使用昵称（如 `张三`）进行登录，提升用户体验。

**实现方案**：
1. **数据库层**：为 `users` 表的 `nickname` 字段添加唯一索引（`UNIQUE INDEX uq_nickname`）
2. **持久层**：在 `UserMapper` 新增 `selectByNickname` 方法
3. **服务层**：
   - 注册时校验昵称唯一性，防止重复
   - 登录时先按 `username` 查询，若未找到则按 `nickname` 再查一次
4. **控制器层**：更新 Swagger 注释说明支持昵称登录

**关键代码**：
```java
// UserServiceImpl.java - 登录逻辑
public String login(String username, String password) {
    // 支持使用系统用户名或唯一昵称登录
    User user = userMapper.selectByUsername(username);
    if (user == null) {
        user = userMapper.selectByNickname(username);
    }
    // ... 校验密码并返回 Token
}
```

**优点**：
- 用户体验友好：记不住数字ID也能用昵称登录
- 兼容性好：保持原有 `username` 字段名，前端无需修改代码
- 安全性强：数据库唯一索引 + 应用层双重校验

### 2.2 按昵称搜索用户（公开接口）

**需求背景**：  
前端需要提供用户搜索功能，方便查找其他用户（如查看某用户的所有评价）。

**实现方案**：
1. **接口路径**：`GET /api/users/search?nickname=xxx`
2. **权限**：公开接口，无需登录
3. **安全设计**：仅返回脱敏后的基本信息（id、username、nickname、createdAt），不暴露密码、邮箱等敏感数据
4. **查询逻辑**：使用 MyBatis-Plus 的 `QueryWrapper.like` 实现模糊查询

**关键代码**：
```java
// UserServiceImpl.java
public List<User> searchByNickname(String keyword) {
    QueryWrapper<User> queryWrapper = new QueryWrapper<>();
    queryWrapper.like("nickname", keyword.trim())
            .eq("is_active", 1)
            .select("id", "username", "nickname", "created_at"); // 仅返回非敏感字段
    return userMapper.selectList(queryWrapper);
}
```

**前端使用示例**：
```javascript
fetch('http://localhost:7070/api/users/search?nickname=张')
  .then(res => res.json())
  .then(result => {
    console.log('找到用户:', result.data);
  });
```

### 2.3 管理员修改用户昵称

**需求背景**：  
管理员需要能够修改用户昵称（如处理违规昵称、应用户要求修改等）。

**实现方案**：
1. **接口路径**：`PUT /api/admin/users/{id}/nickname`
2. **权限**：仅 `ROLE_ADMIN` 可访问
3. **业务逻辑**：
   - 校验新昵称长度（不超过50字符）
   - 检查用户是否存在
   - 若昵称未变化，直接返回成功
   - 校验新昵称是否已被其他用户占用
   - 更新昵称并记录日志

**关键代码**：
```java
// UserServiceImpl.java
public void updateUserNickname(Long userId, String newNickname) {
    // 1. 参数校验
    if (newNickname == null || newNickname.trim().isEmpty()) {
        throw new IllegalArgumentException("昵称不能为空");
    }
    
    // 2. 检查用户是否存在
    User user = userMapper.selectById(userId);
    if (user == null || user.getIsActive() == 0) {
        throw new IllegalArgumentException("用户不存在");
    }
    
    // 3. 昵称未变化，直接返回
    if (user.getNickname().equals(newNickname.trim())) {
        return;
    }
    
    // 4. 校验新昵称是否已被占用
    User existByNick = userMapper.selectByNickname(newNickname.trim());
    if (existByNick != null && !existByNick.getId().equals(userId)) {
        throw new IllegalArgumentException("昵称已被其他用户使用，请更换");
    }
    
    // 5. 更新昵称
    user.setNickname(newNickname.trim());
    userMapper.updateById(user);
    log.info("管理员修改用户昵称成功: userId={}, newNickname={}", userId, newNickname);
}
```

## 三、数据库变更

### 3.1 Schema 更新

**文件**：`backend/src/main/resources/sql/schema.sql`

**变更内容**：
```sql
-- 将 nickname 索引从普通索引改为唯一索引
CREATE TABLE IF NOT EXISTS users (
    -- ... 其他字段 ...
    nickname VARCHAR(50) NOT NULL COMMENT '昵称（用户设置，用于评论展示）',
    -- ... 其他字段 ...
    INDEX idx_username (username),
    UNIQUE INDEX uq_nickname (nickname),  -- 改为唯一索引
    INDEX idx_roles (roles)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

## 七、安全设计

### 7.1 昵称唯一性保障

**双重校验机制**：
1. **应用层**：注册时 `selectByNickname` 校验，修改时再次校验
2. **数据库层**：`UNIQUE INDEX uq_nickname` 作为最后防线

### 7.2 数据脱敏

**公开搜索接口**：
- 仅返回：`id`、`username`、`nickname`、`createdAt`
- 不返回：`passwordHash`、`email`、`roles`、`isActive`

### 7.3 权限控制

| 功能 | 权限要求 |
|------|---------|
| 搜索用户 | 公开（无需登录） |
| 修改昵称 | 仅管理员（`ROLE_ADMIN`） |
| 用户登录 | 公开 |
| 用户注册 | 公开 |

## 八、已知限制与后续优化

### 8.1 当前限制

1. **无操作审计**：管理员修改昵称的操作未记录到审计表
2. **无频率限制**：公开搜索接口可能被滥用
3. **无分页**：搜索结果不支持分页（用户量大时可能影响性能）

### 8.2 优化建议

1. **审计日志**：新增 `user_audit_log` 表记录管理员操作
2. **接口限流**：对公开搜索接口增加 Redis 限流（如每分钟10次）
3. **分页支持**：为搜索接口增加 `page`、`size` 参数
4. **缓存优化**：对热门昵称的搜索结果增加缓存（TTL 5分钟）
