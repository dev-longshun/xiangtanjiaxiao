**项目说明 — 后端迁移与架构说明**

概述：
- 目标：将前端静态 JSON 数据迁移为后端服务（Spring Boot）+ MySQL 持久化，使用 MyBatis-/MyBatis-Plus 做数据访问，认证采用 JWT，保留前端 React 代码但改为通过 REST API 获取数据与投稿。
- 范围：设计数据库 schema、生成建表 SQL、提供迁移脚本、搭建后端工程骨架（目录/启动代码示例）、以及前端最小改造说明。

一、技术栈（已确认）
- 后端：Spring Boot 3.x
- 持久层：MyBatis-Plus + MyBatis（结合使用）
- 数据库：MySQL 8.x（utf8mb4，InnoDB）
- 认证：JWT（Access Token；可选 Refresh Token）
- 前端：现有 React + Vite，改为通过 REST API 获取数据

二、主要目标与设计要点
- 保留现有 `id`（如 `school-001`）以简化迁移。
- `tags` 与 `courses` 初期以 JSON 字段存储；如需复杂查询，可改为关联表。
- 所有用户投稿初始状态为 `pending`，管理员审核后置为 `approved`。

三、建表 SQL（草案）
- `users`（管理员账号）
```
CREATE TABLE users (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  username VARCHAR(100) NOT NULL UNIQUE,
  password_hash VARCHAR(255) NOT NULL,
  display_name VARCHAR(100),
  email VARCHAR(150),
  roles VARCHAR(100) NOT NULL,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  is_active TINYINT(1) DEFAULT 1

```

- `schools`
```
CREATE TABLE schools (
  id VARCHAR(50) PRIMARY KEY,
  name VARCHAR(200) NOT NULL,
  name_pinyin VARCHAR(255),

  description TEXT,
  rating DECIMAL(3,1) DEFAULT 0.0,
  review_count INT DEFAULT 0,

CREATE INDEX idx_schools_name ON schools(name);

```

- `reviews`
```
CREATE TABLE reviews (
  id VARCHAR(50) PRIMARY KEY,
  school_id VARCHAR(50) NOT NULL,
  author VARCHAR(100),
  content TEXT,
  rating TINYINT NOT NULL,
  date DATE,
  tags JSON,
  status ENUM('pending','approved','rejected') DEFAULT 'pending',
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  reviewed_at DATETIME NULL,
  reviewed_by BIGINT NULL,
  FOREIGN KEY (school_id) REFERENCES schools(id) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
CREATE INDEX idx_reviews_school ON reviews(school_id);
CREATE INDEX idx_reviews_status ON reviews(status);
```

四、主要 REST API（示例，RESTful 风格分为用户接口和管理接口）

1) 用户接口（对外 `/api/*`，公开或基于用户登录权限）
  - GET `/api/schools` — 驾校列表（分页/排序/搜索）
  - GET `/api/schools/{id}` — 驾校详情
  - GET `/api/schools/{id}/reviews` — 某驾校评价列表
  - POST `/api/reviews` — 投稿（status 默认 `pending`）
  - GET `/api/data/summary` — 首页统计（覆盖数、评价数、平均通过率等）
  - POST `/api/auth/login` — 用户/管理员登录（返回 JWT）

2) 管理接口（统一前缀 `/api/admin/*`，需 `ROLE_ADMIN` 权限）
  - GET `/api/admin/reviews?status=pending` — 待审核评价列表
  - POST `/api/admin/reviews/{id}/approve` — 审核通过（同时更新 schools 的 rating、review_count）
  - POST `/api/admin/reviews/{id}/reject` — 驳回并记录原因
  - POST `/api/admin/schools` — 新增驾校
  - PUT `/api/admin/schools/{id}` — 编辑驾校
  - DELETE `/api/admin/schools/{id}` — 删除驾校
  - GET `/api/admin/stats` — 管理端统计概览

说明：管理接口全部集中在 `/api/admin` 下，便于权限控制、网关路由与运维监控；前端与 API 网关可根据前缀区分流量与限流策略。

五、认证与初始管理员
- 使用 `BCryptPasswordEncoder` 存储密码哈希；JWT 签名密钥通过环境变量 `JWT_SECRET` 注入。
- 初始管理员：`username=admin`，初始密码 `123456`（系统启动时由初始化脚本/CommandLineRunner 创建，密码以 bcrypt 存储）。

六、数据迁移策略
- 提供两种迁移工具选项：
  1. Java `CommandLineRunner`（推荐）: 在后端项目里实现数据导入，读取仓库 `src/data/data.json` 并写入 MySQL；优点：事务支持、同语言维护。
  2. Node.js 脚本：基于 `mysql2` 或 `knex` 实现数据导入，适合维护者熟悉 Node 场景。
- 迁移流程：备份 -> 导入 schools -> 导入 reviews（status `approved` 或 `pending`）-> 更新 schools 的 rating 与 review_count -> 验证样例数据。

七、前端改造要点
- 用 `fetch` 或 `axios` 替换 `import data from '../data/data.json'`，通过环境变量 `VITE_API_BASE` 指向后端 API。
- 在 `Submit` 页面添加真实投稿表单，POST 到 `/api/v1/reviews` 并显示“已收到，等待审核”。

十一、后端工程目录结构（建议）
以下为推荐的 `backend/` Maven 项目目录结构示例，便于代码组织与后续扩展：

```
backend/
├─ pom.xml
├─ src/
│  ├─ main/
│  │  ├─ java/com/xiangtan/jiaxiao/
│  │  │  ├─ config/          # Security、MyBatis、JWT 等配置类
│  │  │  ├─ controller/      # REST 控制器（public + admin）
│  │  │  ├─ service/         # 业务逻辑层
│  │  │  ├─ mapper/          # MyBatis / MyBatis-Plus Mapper
│  │  │  ├─ model/           # entity / dto / vo
│  │  │  ├─ util/            # JwtUtil、PinyinUtil 等工具
│  │  │  └─ bootstrap/       # 应用启动数据（初始化 admin、迁移工具入口）
│  │  └─ Application.java
│  └─ resources/
│     ├─ application.yml
│     ├─ mybatis/           # 如使用 XML mapper，放在此处
│     └─ static/
└─ test/
```

说明：
- `config`：放 Spring Security/JWT 配置（如 `SecurityConfig`）、全局异常处理、跨域配置等。
- `controller`：分为 `public`（或 `user`）和 `admin` 包，URL 设计遵循 `/api/v1/...`（用户接口）与 `/api/v1/admin/...`（管理接口）的约定；使用注解和配置对管理接口统一鉴权。
- `bootstrap`：用于放置 `CommandLineRunner` 实现，例如导入 JSON 数据或创建初始 admin。

十二、Swagger（使用 springdoc-openapi 的 Swagger UI，仅启用 Swagger UI）
为了方便开发与 API 调试，后端将只集成 Swagger UI（基于 `springdoc-openapi` 实现），用于生成交互式 API 文档和测试接口。

1) Maven 依赖示例（添加到 `pom.xml`）：
```xml
<dependency>
  <groupId>org.springdoc</groupId>
  <artifactId>springdoc-openapi-starter-webmvc-ui</artifactId>
  <version>2.1.0</version>
</dependency>
```

2) 基本配置（`application.yml` 示例）：
```yaml
spring:
  mvc:
    pathmatch:
      matching-strategy: ANT_PATH_MATCHER

springdoc:
  swagger-ui:
    path: /swagger-ui.html
```

3) 简单的 Swagger 配置（可选 Java 配置类，用于填写标题/描述）：
```java
@Configuration
public class SwaggerConfig {
    @Bean
    public OpenAPI customOpenAPI() {
        return new OpenAPI()
            .info(new Info().title("湘潭驾校评价 API").version("v1").description("后端 API 文档（Swagger UI）"));
    }
}
```

4) 使用说明：
- 启动后端服务后，访问 `http://localhost:8080/swagger-ui.html`（或 `http://localhost:8080/swagger-ui/index.html`）即可打开交互式 Swagger UI 页面，页面会基于后端注解自动生成接口列表并允许在线调试。
-- Swagger UI 会展示所有标记的接口，包括 `/api` 下的用户接口与 `/api/admin` 下的管理接口。注意：管理接口在文档中可见，但在生产环境应限制访问或要求登录才能操作。
- 如果需要机器可读的 OpenAPI JSON，可通过 `http://localhost:8080/v3/api-docs` 获取（但本方案以 Swagger UI 为主）。

5) 开发/生产注意：
- 在生产环境建议限制 Swagger UI 的访问（例如仅允许内网或通过认证访问），或在 `application-prod.yml` 中禁用：
```yaml
springdoc:
  swagger-ui:
    enabled: false
```
