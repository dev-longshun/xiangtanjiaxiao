**实现日期**：2025年12月5日  
**功能版本**：v1.3  
**实现范围**：后端 JWT Token 黑名单机制 + 退出登录接口

## 一、核心问题与解决方案

### 问题
原有 JWT 认证系统存在的问题：
- Token 一旦签发，在有效期内始终有效，无法主动失效
- 用户点击"退出登录"后，旧 Token 仍然可以使用（安全隐患）
- 如果 Token 被泄露，无法立即使其失效

### 解决方案
实现 **Token 黑名单机制**：
1. 用户退出登录时，将 Token 加入黑名单
2. 请求时检查 Token 是否在黑名单中
3. 定期清理已过期的 Token（节省内存）

## 三、核心代码

### 3.1 TokenBlacklistManager（黑名单管理器）

```java
@Component
public class TokenBlacklistManager {
    // 内存黑名单：key = token, value = 过期时间（毫秒）
    private final ConcurrentHashMap<String, Long> blacklist = new ConcurrentHashMap<>();
    
    // 定时清理线程：每5分钟清理一次过期 Token
    private final ScheduledExecutorService scheduler = 
        Executors.newScheduledThreadPool(1);
    
    // 添加 Token 到黑名单
    public void addToBlacklist(String token, long expiryTime) {
        blacklist.put(token, expiryTime);
    }
    
    // 检查 Token 是否在黑名单中
    public boolean isBlacklisted(String token) {
        return blacklist.containsKey(token);
    }
    
    // 定时清理过期 Token
    private void cleanupExpiredTokens() {
        long now = System.currentTimeMillis();
        for (String token : blacklist.keySet()) {
            if (blacklist.get(token) <= now) {
                blacklist.remove(token);
            }
        }
    }
}
```

### 3.3 退出登录接口

```java
@PostMapping("/logout")
@Operation(summary = "用户退出登录")
public Result<?> logout(HttpServletRequest request) {
    // 1. 提取 Token
    String token = extractToken(request);
    
    if (token == null) {
        return Result.error(401, "未找到有效的 Token");
    }

    // 2. 验证 Token
    if (!jwtUtil.validateToken(token)) {
        return Result.error(401, "Token 无效或已过期");
    }

    // 3. 获取 Token 过期时间
    long expiryTime = jwtUtil.getExpiryTimeFromToken(token);
    
    // 4. 将 Token 加入黑名单
    blacklistManager.addToBlacklist(token, expiryTime);
    
    return Result.success(null, "退出登录成功");
}
```

  "code": 200,
  "data": null,
  "message": "退出登录成功"
}

**响应失败**：

  "code": 401,
  "data": null,
  "message": "Token 无效或已过期"

## 五、前端集成

### 登出处理流程

```javascript
async function logout() {
  const token = localStorage.getItem('token');
  
  try {
    // 1. 调用后端退出接口
    const response = await fetch('/api/auth/logout', {
      method: 'POST',
      headers: {
        'Authorization': 'Bearer ' + token
      }
    });
    
    const result = await response.json();
    console.log('后端退出结果:', result);
    
  } finally {
    // 2. 无论成功或失败，都清除本地 Token
    localStorage.removeItem('token');
    localStorage.removeItem('username');
    
    // 3. 跳转到登录页
    window.location.href = '/login';
  }
}
```

## 六、技术亮点

### 6.1 并发安全
- 使用 `ConcurrentHashMap` 而非普通 HashMap
- 支持高并发的添加和查询操作

### 6.2 内存优化
- 后台线程定期清理过期 Token
- 黑名单大小恒定，不会无限增长
- 适合中等规模系统（单机万级并发）

### 6.3 无状态与有状态结合
- 保留 JWT 的无状态优势（无需数据库查询）
- 通过黑名单获得"半有状态"能力（支持主动失效）
- 兼顾了两种方案的优点

### 6.4 生产级别代码
- 完整的日志记录
- 异常处理完善
- 性能高效（O(1) 操作）
