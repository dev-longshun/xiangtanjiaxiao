## 一、系统权限体系

### 1.1 角色划分

系统共分为 **2 个角色**：

| 角色 | 值 | 权限 | 说明 |
|------|-----|------|------|
| 普通用户 | `ROLE_USER` | 投稿评价、上传图片 | 注册后默认角色 |
| 管理员 | `ROLE_ADMIN` | 审核评价、管理驾校、修改用户 | 需要特殊设置 |

### 1.2 权限对应的接口

| 权限级别 | 接口路径 | 说明 |
|---------|--------|------|
| **公开** | `/api/auth/**` | 登录、注册、退出 |
| **公开** | `/api/schools/**` | 查看驾校列表、详情、搜索 |
| **公开** | `/api/reviews/school/*` | 查看某驾校的评价 |
| **公开** | `/api/users/search` | 搜索用户 |
| **USER** | `POST /api/reviews` | 投稿评价 |
| **USER** | `GET /api/reviews/my` | 查看我的投稿 |
| **USER** | `POST /api/upload/image` | 上传图片 |
| **ADMIN** | `/api/admin/**` | 管理驾校、审核评价、修改用户 |

## 二、权限认定流程图

### 2.1 完整流程

```
┌─────────────────────────────────────────────────────────────┐
│  用户发起 HTTP 请求                                          │
│  (可能携带 Authorization: Bearer {token} 请求头)            │
└──────────────────────────┬──────────────────────────────────┘
                           ↓
        ┌──────────────────────────────────────────┐
        │  SecurityFilterChain                     │
        │  (Spring Security 过滤链)                │
        └──────────────┬──────────────────────────┘
                       ↓
        ┌──────────────────────────────────────────┐
        │  1️⃣ JwtAuthenticationFilter              │
        │  (JWT 认证过滤器)                       │
        └──────────────┬──────────────────────────┘
                       ↓
        ┌──────────────────────────────────────────┐
        │  提取 Token                             │
        │  Authorization: Bearer {token}           │
        └──────────────┬──────────────────────────┘
                       ↓
        ┌──────────────────────────────────────────┐
        │  验证 Token                             │
        │  - 检查签名是否有效                      │
        │  - 检查是否过期                          │
        │  - 检查是否在黑名单中                    │
        └──────────────┬──────────────────────────┘
                      / \
                    YES   NO
                   /       \
                  ✓         ✗ (结束，无 Authentication)
                 │
                 ↓
        ┌──────────────────────────────────────────┐
        │  2️⃣ 解析 Token 内容                      │
        │  提取：username, roles, userId           │
        └──────────────┬──────────────────────────┘
                       ↓
        ┌──────────────────────────────────────────┐
        │  3️⃣ 转换角色                            │
        │  roles 字符串 → GrantedAuthority 列表    │
        │  例如：                                  │
        │  "ROLE_ADMIN,ROLE_USER"                  │
        │  → [ROLE_ADMIN, ROLE_USER]              │
        └──────────────┬──────────────────────────┘
                       ↓
        ┌──────────────────────────────────────────┐
        │  4️⃣ 创建 Authentication 对象            │
        │  设置：                                 │
        │  - principal: username                   │
        │  - credentials: null                     │
        │  - authorities: [ROLE_ADMIN, ...]       │
        └──────────────┬──────────────────────────┘
                       ↓ 
        ┌──────────────────────────────────────────┐
        │  5️⃣ 放入 SecurityContext                │
        │  SecurityContextHolder.getContext()      │
        │  .setAuthentication(authentication)      │
        └──────────────┬──────────────────────────┘
                       ↓
        ┌──────────────────────────────────────────┐
        │  6️⃣ authorizeHttpRequests 检查权限       │
        │  根据请求路径和角色进行权限校验         │
        └──────────────┬──────────────────────────┘
                       ↓
        ╔════════════════════════════════════════╗
        ║  权限校验规则                          ║
        ╠════════════════════════════════════════╣
        ║ 请求路径                   所需权限    ║
        ╠════════════════════════════════════════╣
        ║ /api/auth/**               permitAll   ║
        ║ /api/schools/**            permitAll   ║
        ║ /api/reviews/school/*      permitAll   ║
        ║ /api/users/search          permitAll   ║
        ║                                        ║
        ║ POST /api/reviews          USER/ADMIN  ║
        ║ GET /api/reviews/my        USER/ADMIN  ║
        ║ POST /api/upload/image     USER/ADMIN  ║
        ║                                        ║
        ║ /api/admin/**              ADMIN       ║
        ╚════════════════════════════════════════╝
                       ↓
                      / \
                   PASS   FAIL
                   /       \
                  ✓         ✗
                  │         │
            ┌─────┴─┐   ┌───┴────────────────────┐
            ↓       │   │  权限检查失败           │
         执行      │   │  → AccessDeniedException│
         请求      │   │  → 返回 403 Forbidden   │
                   │   └────────────────────────┘
                   │
            ┌──────┴────────────────────────────┐
            ↓                                   ↓
        ┌─────────────────┐         ┌─────────────────────────┐
        │ 返回 200 响应   │         │ CustomAccessDeniedHandler│

                                    ┌──────────────────────┐

                                    │ }                   │
```

### 2.2 未登录情况

```
用户未登录，未提供 Token
    ↓
JwtAuthenticationFilter 无 Token 可提取
    ↓
SecurityContext 中无 Authentication
    ↓
访问受保护资源（如 /api/reviews）
    ↓
authorizeHttpRequests 要求认证
    ↓
抛出 AuthenticationException
    ↓
CustomAuthenticationEntryPoint 捕获
    ↓
返回 401 JSON 响应
{
  "error": "未授权",
  "message": "请先登录或提供有效的 Token",
  "status": 401
}
```

## 三、详细实现

### 3.1 SecurityConfig（权限配置核心）

```java
@Bean
public SecurityFilterChain securityFilterChain(HttpSecurity http) throws Exception {
    http
        // 添加 JWT 过滤器
        .addFilterBefore(jwtAuthenticationFilter, UsernamePasswordAuthenticationFilter.class)
        
        // 权限校验规则
        .authorizeHttpRequests(auth -> auth
            // 1. 公开接口（无需认证）
            .requestMatchers(
                "/api/auth/**",              // 登录、注册、退出
                "/api/schools",              // 驾校列表
                "/api/reviews/school/*",     // 查看评价
                "/api/users/search"          // 搜索用户
            ).permitAll()
            
            // 2. 需要 USER 或 ADMIN 角色
            .requestMatchers(
                "/api/reviews",              // 投稿评价
                "/api/reviews/my",           // 我的投稿
                "/api/upload/image"          // 上传图片
            ).hasAnyRole("USER", "ADMIN")
            
            // 3. 仅 ADMIN
            .requestMatchers("/api/admin/**").hasRole("ADMIN")
            
            // 4. 其他要求认证
            .anyRequest().authenticated()
        )
        
        // 异常处理
        .exceptionHandling(ex -> ex
            .authenticationEntryPoint(authenticationEntryPoint)  // 401
            .accessDeniedHandler(accessDeniedHandler)            // 403
        );
    
    return http.build();
}
```

### 3.2 JwtAuthenticationFilter（关键实现）

```java
@Override
protected void doFilterInternal(HttpServletRequest request, 
                                HttpServletResponse response, 
                                FilterChain filterChain) {
    
    // 1️⃣ 提取 Token
    String token = extractToken(request);
    
    // 2️⃣ 验证 Token
    if (token != null && jwtUtil.validateToken(token) && !blacklistManager.isBlacklisted(token)) {
        
        // 3️⃣ 从 Token 中获取用户信息
        String username = jwtUtil.getUsernameFromToken(token);     // "10001"
        String roles = jwtUtil.getRolesFromToken(token);           // "ROLE_ADMIN"
        
        // 4️⃣ 转换角色为 GrantedAuthority 列表
        List<SimpleGrantedAuthority> authorities = parseRoles(roles);
        // 结果：[SimpleGrantedAuthority("ROLE_ADMIN")]
        
        // 5️⃣ 创建 Authentication 对象
        UsernamePasswordAuthenticationToken authentication = 
            new UsernamePasswordAuthenticationToken(
                username,           // principal (用户标识)
                null,              // credentials (密码，JWT 为 null)
                authorities        // authorities (权限列表)
            );
        
        // 6️⃣ 放入 SecurityContext
        SecurityContextHolder.getContext().setAuthentication(authentication);
    }
    
    // 7️⃣ 继续过滤链，进入权限检查阶段
    filterChain.doFilter(request, response);
}

/**
 * 解析角色字符串为 GrantedAuthority 列表
 * 支持单角色或多角色
 */
private List<SimpleGrantedAuthority> parseRoles(String roles) {
    if (roles == null || roles.trim().isEmpty()) {
        return Arrays.asList(new SimpleGrantedAuthority("ROLE_USER"));
    }
    
    return Arrays.stream(roles.split(","))
            .map(String::trim)
            .map(SimpleGrantedAuthority::new)
            .collect(Collectors.toList());
}
```

### 3.3 角色存储和提取

**数据库中的存储**（User 表）：

```
id    username    roles
1     admin       ROLE_ADMIN
2     10001       ROLE_USER
3     10002       ROLE_ADMIN,ROLE_USER
```

**JWT Token 中的存储**（Payload）：

```json
{
  "sub": "10001",
  "userId": 1,
  "username": "10001",
  "roles": "ROLE_USER",        // 字符串格式，多个用逗号分隔
  "iat": 1733328000,
  "exp": 1733414400
}
```

**认证对象中的存储**（Authentication）：

```
authentication.getPrincipal()    // "10001"
authentication.getAuthorities()  // [GrantedAuthority("ROLE_USER")]
authentication.getCredentials()  // null (JWT 无密码)
```

## 四、权限检查逻辑

### 4.1 permitAll（允许所有）

```java
.requestMatchers("/api/auth/**").permitAll()
```

**检查流程**：
```
请求 → /api/auth/login
    ↓
权限检查：permitAll
    ↓
✓ 通过（无需认证）
```

### 4.2 hasAnyRole（任意一个角色）

```java
.requestMatchers("/api/reviews").hasAnyRole("USER", "ADMIN")
```

**检查流程**：
```
请求 → POST /api/reviews（用户投稿评价）
    ↓
获取 Authentication
    ↓
检查 authorities 中是否包含：
  - ROLE_USER ✓
  - ROLE_ADMIN ✓
    ↓
✓ 有任意一个 → 通过
✗ 都没有 → 拒绝 403
```

**具体例子**：

```
情况1：用户有 ROLE_USER
  authorities = [ROLE_USER]
  check: ROLE_USER or ROLE_ADMIN?
  → 包含 ROLE_USER ✓
  → 允许访问

情况2：用户有 ROLE_ADMIN
  authorities = [ROLE_ADMIN]
  check: ROLE_USER or ROLE_ADMIN?
  → 包含 ROLE_ADMIN ✓
  → 允许访问

情况3：用户无任何角色
  authorities = []
  check: ROLE_USER or ROLE_ADMIN?
  → 都不包含 ✗
  → 拒绝访问 403
```

### 4.3 hasRole（必须这个角色）

```java
.requestMatchers("/api/admin/**").hasRole("ADMIN")
```

**检查流程**：
```
请求 → /api/admin/reviews/1/review（审核评价）
    ↓
获取 Authentication
    ↓
检查 authorities 中是否包含：
  - ROLE_ADMIN
    ↓
✓ 包含 → 通过
✗ 不包含 → 拒绝 403
```

### 4.4 authenticated（任何已登录用户）

```java
.anyRequest().authenticated()
```

**检查流程**：
```
请求 → /api/其他接口
    ↓
SecurityContext 中是否有 Authentication?
    ↓
✓ 有（已登录）→ 通过
✗ 无（未登录）→ 抛出 AuthenticationException → 401
```

## 五、异常处理

### 5.1 未登录（401）

**触发条件**：
- 访问受保护资源时，未提供 Token 或 Token 无效

**处理器**：`CustomAuthenticationEntryPoint`

**返回响应**：
```json
HTTP 401 Unauthorized
Content-Type: application/json

{
  "error": "未授权",
  "message": "请先登录或提供有效的 Token",
  "status": 401,
  "path": "/api/reviews"
}
```

### 5.2 权限不足（403）

**触发条件**：
- 已登录，但权限不足

**处理器**：`CustomAccessDeniedHandler`

**返回响应**：
```json
HTTP 403 Forbidden
Content-Type: application/json

{
  "error": "权限不足",
  "message": "您没有访问此资源的权限",
  "status": 403,
  "path": "/api/admin/schools"
}
```

## 六、实际请求示例

### 6.1 普通用户投稿评价

```bash
# 1. 用户登录
curl -X POST http://localhost:7070/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"10001","password":"123456"}'

# 响应：
# {"code":200,"data":{"token":"eyJhbGci..."},"message":"登录成功"}

TOKEN="eyJhbGci..."

# 2. 使用 Token 投稿评价（需要 ROLE_USER）
curl -X POST http://localhost:7070/api/reviews \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $TOKEN" \
  -d '{
    "schoolId":"changsha-anjia",
    "author":"张三",
    "content":"教练很负责",
    "rating":5
  }'

# 请求流程：
# 1️⃣ 提取 Token → "eyJhbGci..."
# 2️⃣ 验证 Token → ✓ 有效
# 3️⃣ 解析 Token → username="10001", roles="ROLE_USER"
# 4️⃣ 创建 Authentication → authorities=[ROLE_USER]
# 5️⃣ 检查权限 → /api/reviews 需要 ROLE_USER or ROLE_ADMIN
# 6️⃣ 检查结果 → ✓ 有 ROLE_USER
# 7️⃣ 允许通过 → 执行投稿逻辑

# 响应：
# {"code":200,"data":null,"message":"评价已提交，等待管理员审核"}
```

### 6.2 普通用户试图访问管理接口

```bash
# 用户试图修改驾校信息（仅管理员可做）
curl -X PUT http://localhost:7070/api/admin/schools/changsha-anjia \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $TOKEN" \
  -d '{"name":"新名称"}'

# 请求流程：
# 1️⃣ 提取 Token → "eyJhbGci..."
# 2️⃣ 验证 Token → ✓ 有效
# 3️⃣ 解析 Token → username="10001", roles="ROLE_USER"
# 4️⃣ 创建 Authentication → authorities=[ROLE_USER]
# 5️⃣ 检查权限 → /api/admin/schools 需要 ROLE_ADMIN
# 6️⃣ 检查结果 → ✗ 只有 ROLE_USER，不是 ROLE_ADMIN
# 7️⃣ 拒绝通过 → AccessDeniedException
# 8️⃣ 调用 CustomAccessDeniedHandler

# 响应：
HTTP 403 Forbidden
{
  "error": "权限不足",
  "message": "您没有访问此资源的权限",
  "status": 403,
  "path": "/api/admin/schools/changsha-anjia"
}
```

### 6.3 未登录用户试图投稿

```bash

  "error": "未授权",
  "message": "请先登录或提供有效的 Token",
```

## 八、权限决策树

```
用户请求资源
    ↓
是否是公开接口（permitAll）？
├─ YES → ✓ 通过
└─ NO → 继续

是否有有效的 Token？
├─ NO → ✗ 返回 401（CustomAuthenticationEntryPoint）
└─ YES → 继续

Token 是否在黑名单中？
├─ YES → ✗ 返回 401
└─ NO → 继续

是否需要特定权限？
├─ NO（authenticated） → ✓ 通过
└─ YES → 继续

检查用户角色是否满足权限要求
├─ YES → ✓ 通过，执行请求
└─ NO → ✗ 返回 403（CustomAccessDeniedHandler）
```

## 总结

**权限认定完整流程**：

1. **请求到达** → 携带 Token
2. **Token 验证** → JwtAuthenticationFilter 提取并验证
3. **角色解析** → 从 Token 中获取角色信息
4. **权限转换** → 转为 GrantedAuthority 列表
5. **放入上下文** → 设置到 SecurityContext
6. **权限检查** → 根据规则检查是否有权限
7. **执行或拒绝** → 允许通过或返回 401/403

**所有权限检查都由 Spring Security 自动完成，开发者只需要在 SecurityConfig 中定义规则即可！**
